# メタの自動追加抑制・CSV保存・追加と置換

基準main: 083f7112091ade636e7ab402e2516b05bb9bb088。
原因は全合法技を列挙し、最高平均Ratingから20以内の構成をすべて追加していたこと。手動構成に対する新しい対応の有無を問わず増えていた。

## 操作

- 選択中のメタを「CSVをダウンロード」で全件保存。UTF-8 BOM付き4列CSVで、既存のTXT/CSV入力へ再取り込みできる。コピーは従来の100件区切りを維持する。
- カスタムメタ欄の保存方法で「別名」「選択中の手動構成へ追加」「選択中を全置換」を選ぶ。コピペ・ファイルの両方でプレビュー後に保存する。追加は同じ種の別技を保持し、全置換は入力にない行を除く。公式プリセットの直接更新は拒否し別名保存へ誘導する。
- 「自動追加を見直す」は由来が記録されている自動追加を外して手動構成から再判定する。由来不明の構成は削除しない。過去の全構成を見直す場合は元の入力を全置換する。
- 手動の原本(source_csv)と拡張結果(csv)を分ける。追加のプレビューも手動原本から作る。新規保存・上書き・見直し後に追加判定を行い、編集内容を勝手に書き換えない。履歴・IV結果・認証・ボリュームを初期化しない。

## 判定と上限

- 入力順の先頭8種を対象に各最大6つの追加候補を安価な技効率・タイプ/効果の違いで絞る。手動構成はすべて維持する。
- 対戦相手は入力順で各種最初の技構成を最大32種。標準IV・6シールドで比較する。
- 同じシールド条件で全手動構成がRating<=500、追加候補が>=550となる相手が2種以上増える場合だけ採用。相手の技違いやシールド違いを複数種と数えない。
- 新しく対応できる種が多い候補を各種1件、全体8件まで採用。手動原本と合わせ500行を超えない。平均Ratingの近さだけでは追加しない。
- 技性能データ不足・unknownでは追加の根拠にせず、メテノは自動評価の標本から除く。全技・全メタの最適性や実戦勝率の保証ではない。
- 旧方式の未完ジョブは再開せずobsoleteにする。新方式は種ごとの結果を保存して再開可能。同じゲームデータ・原本ハッシュの結果を再利用し、更新された保存先への古い結果の適用を拒否する。

## 保護と検証

更新は既存のサーバーロック、revision、旧内容SHAとプレビューSHAの照合、合法性検証、原子的ファイル置換、バックアップを再利用。計算中は更新を拒否し、進行中の計算は既存の不変スナップショットで継続する。

固定GameMaster・手動6構成で内部Directエンジンを使用した3回中央値: 旧1.0729秒/205候補/32件追加、新0.3426秒/41候補/3件追加。追加判定時間は約68%減。この標本はCPU負荷のある同一環境の比較であり、本番全メタやユーザーの厳選全体の所要時間は未測定。
再現: `PYTHONPATH=.:tests python tests/benchmark_meta_minimal.py`。

テストは実エンジンの入力保持と候補上限、対応増分の判定、同種重複集計防止、原本保持・復元・競合・バックアップ、ブラウザーJSでCSV内容とダウンロード、追加・置換・見直し、古い応答の破棄を対象とする。Android実機のファイル保存先・再取り込み操作は別途確認が必要。

学習: 平均値が近い候補を並べるより、既存の指定で不足する役割を追加条件にする。手動原本と生成結果の分離は、生成済みデータを次回の入力として再増殖させないためにも必要。
