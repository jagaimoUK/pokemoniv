# Selective moveset comparison and saved configurations

Automatic comparison now defaults to `smart`, rather than simulating every legal combination. The browser enumerates legal profiles cheaply, uses active GameMaster power, energy, duration, typing/STAB and stat effects to estimate competitive profiles, and selects at most six automatic configurations. Weaker same-type/effect moves are pruned and profiles below 85% of the best heuristic score are omitted. A greedy diversity pass favors different fast-move roles, charge coverage, energy bands and buff/debuff effects. The validated PvPoke default is included. These are selection heuristics, not simulated matchup outcomes or guarantees of optimality for the selected meta/IVs. The unselected profiles remain explicitly untested; `all` retains exhaustive comparison.

Input-specified profiles and enabled user registrations bypass this heuristic and its automatic limit. With missing move metadata, only explicit and validated default profiles are used; the UI warns instead of silently reverting to an exhaustive run. Every selected profile still runs the existing complete opponent/shield/IV-mode matrix with every supplied IV. Actual full-matrix means and unique wins continue to determine the final recommendations. The exact-condition result cache remains compatible.

`技の設定` supports adding multiple configurations, selecting them with checkboxes and deleting them. Entries are stored per exact species/form in this browser's `localStorage` under `pvpoke-app-movesets-v1`; they are not server/account-wide storage. Reversed charged-move pairs deduplicate. Invalidated registered moves stop planning and ask for correction. Storage failures keep the current screen usable and state that reload will lose changes. Multi-species imports expose a target selector; the original IVs, CP records, status and source sections remain attached to each independent source group. Manual mode runs all enabled registrations, falling back to the input configuration when no entries are enabled. No strength cutoff is applied to explicitly selected manual profiles.

The results section, including search strings, nicknames and Android export actions, now precedes `カスタムメタを追加`. Completion scrolls/focuses the results. Frozen plans retain their selected jobs, grouping, meta and calculation version on resume; no new shortlisting is performed midway through a resumed batch.

Validation covers 63 to 6 profiles on a synthetic fixture (not an actual species or measured runtime), alternate coverage/effects, explicit weak-profile overrides, persistent selection, duplicate handling, multi-species editing/source isolation, missing metadata, unchanged full-matrix aggregation and mobile/desktop browser interactions.
