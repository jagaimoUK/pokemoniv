# メタプリセットの操作欄を整理

## 原因と変更

スマホ向け共通CSSの `.actions button { flex: 1 }` が、プリセットや設定ボタンにも適用され、余白いっぱいに引き伸ばしていた。

- プリセット欄専用のスタイルに分離。名前に合う幅で折り返す。
- 現在使う名前・構成数と、デフォルト／お気に入りのラベルを分けて表示。
- 候補の選択状態はチェックと背景色、デフォルトは「既定」、お気に入りは星で表示。デフォルトとお気に入りを両方付けた場合も両方見える。
- 押す範囲は高さ44px以上。長い名前は途中で隠さず折り返す。角丸と落ち着いた緑・金色を使用。
- お気に入りは同じ場所の星ボタンで切り替え、デフォルト設定済みのボタンは無効化して状態を明示。再取得は選択欄横の小さなボタン。
- PvPokeへの貼り付け説明は開閉式に整理。

API・保存形式・計算・コピーの内容は変更しない。

## 検証

ローカル回帰246件中245成功、環境依存のメモリ計測1件スキップ。UI JS10ファイル成功。選択状態・お気に入り状態・デフォルト設定済みの無効化を既存テストで確認。

`tools/check_meta_controls_layout.py` は実際のUIをChromiumで表示し、320/390/768/1280pxで横にはみ出さないこと、44px以上の押す範囲、1件だけの選択状態、候補クリックから選択欄の再表示までを確認する。アカウントや本番データは使わない。スクリーンショットはGitHub Actionsの `meta-controls-qa` 成果物に保存する。ブラウザ検証・Dockerビルド・本番配備の最終結果は当該PRの記録を参照。Android実機の手触りは未確認。

## 学習

共有スタイルは便利でも、すべてのボタンが同じ役割とは限らない。プリセットのような小さな選択肢には専用の範囲を設け、共通CSSの影響を限定する。色だけで状態を伝えず、チェック・文字・星も組み合わせると見分けやすくなる。小さく見せることと押す範囲を小さくすることは別で、余白を保ちながら横方向の不要な伸びを止められる。

保存データの変更はないため、コードをrevertして再配備すれば復旧できる。
