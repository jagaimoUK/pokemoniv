# アプリ推薦とGPT評価

既存の `run_iv_selection` の既定値は `report_format:decision` のまま。
GPT評価用のdecision-v2、decision-v1、compactと従来ツールを保持する。

ブラウザ版: https://pokemoniv-production.up.railway.app/app

ChatGPTから `get_catalog` を呼ぶと、認証済みの利用者向けに有効60分の
`app_access.url` が返る。そのリンクを開くと接続キーの手入力は不要。
資格情報はURLフラグメントから読んだ直後にアドレス欄から除去する。
この短期接続はアプリAPIにだけ有効で、MCP操作には使えない。

通常のURLから開く場合は既存サービスの接続キー（Railwayの `PVP_API_KEY`）または、既存認証で
受理される有効なアクセストークンを入力する。接続情報はJavaScriptの
メモリだけに保持し、URL・localStorage・sessionStorageへ保存しない。
現在はブラウザ専用のOAuthログインボタンは未実装。
アプリAPIは既存MCPと同じ認証、許可ユーザー、単一ワーカーを使用する。

## コピペ入力と重要個体値のコピー

「まとめて貼り付け」で次の入力を取り込める。取り込みでは計算を開始しない。

```text
個体値厳選 d
quagsire,MUD_SHOT,AQUA_TAIL,STONE_EDGE
0,11,12
3,13,8
2,15,13
```

`個体値リスト` / `重要個体値`、IVの `0/11/12` 表記、全角数字、
既存の `species,fast,charged1,charged2,level,atk,def,hp` CSVにも対応する。
CSVの元レベルは使わず、既存計算でCP1500以下に合わせる。
入力全体を確認してからフォームに反映し、未読行・異なる種/技構成の混在はエラーにする。
重複IVは取り込み時にまとめ、件数を通知する。
ポケモンや技を省略して現在のフォームを使う場合も明示する。
日本語の種名は既存の登録名に対応し、プリセット外は英語ID・英語名・CSVで指定する。

固定8種の従来クイック選択は互換性のため残す。ブラウザのプリセットは、
有効な従来設定と**現在有効なメタ一覧の全技構成**から生成する。
種IDだけでなく技3つを含むキーで識別するため、同じ種の技違いも選べる。
プリセットの有無にかかわらず、GameMaster全種からの選択・CSV入力を利用できる。

結果冒頭の「重要個体値（コピペ用）」は `攻撃,防御,HP` の1行1体。
推薦と同値代替を重複なしで含め、保留・完全劣後を混ぜない。
個体値だけの一括コピー、種類/技/簡易・詳細モードを含むコマンドコピー、
個別IVコピーを用意する。英語検索式の個別コピーも保持する。

## 判定ルール roles-v1

- 簡易はDefault×6、詳細は4相手IVモード×6。保存ZIPの全候補・全相手を比較。
- 詳細の完全支配は、**同じ代替個体**が24条件のすべてで同等以上、
  かつ1条件以上で上回る場合だけ。モードごとの支配だけで捨てない。
- 全条件で同値の個体は代表と代替として表示し、全代替の検索式を保持。
- 他の入力候補すべてと比較して唯一500超、唯一500で他が500未満、500境界反転の
  勝ち方向の最高候補、または勝ち方向で次点より設定値以上高い候補に役割を付ける。
- 既定の勝ち方向Rating差は20。`selection_policy.meaningful_win_lead` で変更可。
  これは採用価値の仮ルールで、勝敗・残HP・エネルギーの保証ではない。
- **負けたままのRating改善だけでは推薦しない。** 非支配だが根拠不足の
  個体は保留に残す。保持した個体をGPT/人間が追加評価できる。
- 重要相手で独自の500超、または重要相手と不利条件を横断する役割はS候補。
  その他の具体的役割はA候補。PvPoke公式評価ではなく、比較した個体群内の暫定評価。
- 重要相手を省略しても全対面から探す。使用率は推測しない。
  指定名が一致しなければ未一致名を表示する。
- 推薦個体数に上限・最低件数なし。役割の根拠と損失例を実測から表示。
- 英語検索式はGameMasterの種名を使い、IV区分0/1–5/6–10/11–14/15を
  0/1/2/3/4へ変換する。shadowは末尾に `&shadow`。

## 実行・結果の互換性

`run_iv_selection(..., report_format="app")` は新しい `selection` を返す。
計算中は既存の `run_ref` を保存し、`get_iv_selection_result` で同じジョブを取得する。
開始前のパラメータ検証、ZIPの種/技/IV検証、開始時刻の再確認、結果キャッシュは共有する。
アプリ判定ではGPT用レポートを生成せず、各CSVを1度だけ読み込む。

ブラウザの「GPTで評価」は従来decision-v2を作成してコピーできるようにする。
アプリからGPT APIを呼び出したり、API利用料を発生させたりはしない。
ChatGPT内の通常の「個体値厳選」も従来どおりGPT評価で動く。

ブラウザはProjectファイルを直接参照できないので、サーバーのメタスナップショットを
ジョブに固定する。**Project照合済みとは返さない**。ChatGPT経路はProjectの
実SHA256で引き続き照合する。対面の除外・重要名の未一致は画面に表示する。

## 検証

`python -m unittest discover -s tests` で互換性・専門個体・負けたままの改善・
24条件の支配・同値代替・推薦数無制限・検索式・認証とHTTP経路を検証する。
保存済みの実測3個体×87相手×6条件も検証し、各推薦理由のRatingを原行列と照合する。
過去のGPT評価全体との完全一致、端末ごとのログイン、実対戦の勝敗一致は保証しない。
