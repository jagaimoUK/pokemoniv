# CP1500 低スコア検索（2026-10-18 実装）

## 概要とデータ

- データ：個人Libraryに保管されていた2026-10-15付
  `cp1500_all_{overall,leads,closers,switches,chargers,attackers,consistency}_rankings.csv`
  を種名・図鑑番号で整合検証し、スコア部分のみ
  `data/cp1500_role_scores_20261015.json` に統合（1153個体・フォーム行）。
- これは保存時点のPvPokeの役割別順位スコアであり、ボックスでの削除可否の判定ではない。
  他リーグ・将来の環境・進化後・独自の希少性を保証しない。ポケモンGOの個体値は無関係。
- 「未満」は厳密な `score < threshold`。基準ちょうど70.0は検索対象外。

## 選別プリセット（初期値70）

| 選択 | すべて70未満であることを要求する列 | 2026-10-15の数 |
| --- | --- | ---: |
| 推奨 practical | Overall/Leads/Closers/Switches/Chargers/Attackers（Consistency除く） | 211 |
| 総合のみ overall | Overall | 431 |
| 対戦役割 battle | Overall/Leads/Closers/Switches | 422 |
| 全項目 strict | 全7項目 | 3 |

Consistencyのスコアが高い個体が非常に多く、それだけで保護すると検索対象がほぼ消失するため、既定の判定には含めない。「総合のみ」で出た431のうち推奨211との差220件は他の選択役割で70以上。

## 進化後の保護（2026-10-19）

- ボックス整理では進化先も重要。PokeAPI の pokemon_species.csv の進化元図鑑番号を利用した固定スナップショット data/pokemon_species_evolutions_20261019.json（1025種）を参照。分岐進化・2段進化以降の全子孫を調べる。
- もとの個体が低スコアでも、進化先に Overall・Leads・Closers・Switches・Chargers・Attackers のいずれかで基準70以上のものがあれば保護。進化先のスコア未掲載の場合も安全のため保護。
- 例外：ボックス個体のCP値が送られていなくても、安全と証明できる高CP範囲だけを自動検索に含める。PvPoke GameMaster baseStats の保守的な下限比率（進化前は種族値最大＋IV15、進化後は種族値最小＋IV0）から進化後CPが必ず1500を超える現在CPの下限を決める。範囲が確定できない場合は検索式に含めない。
- 高CP例外は Species&cpNNNN-1500&!favorite のような形式。例外が許可されても低いCPの同種ポケモンは保護する。
- ランキングは進化先のPvP性能の参考に過ぎない。自動転送・自動削除は行わない。他リーグ・限定技・図鑑・希少個体は確認が必要。
- 進化系統未登録・英語名未確認・特殊な姿／性別では保守的に保護。元のゲームとPokémon GOで進化条件が異なる場合は追加の照合が必要。

## 1本でボックス整理するモード（2026-10-19）

- 初期表示を「安全優先の検索式1本」に変更し、詳細な英語名検索式は折りたたむ。Androidへ送る検索キューも1本だけ。
- Pokémon GO検索のAND/OR文法は括弧でのネストができず、異なるシャドウ状態・地域条件・CP例外をひとつのOR式で完全表現することはできない。「全てのスコア70未満の種類」を誤りなく1本で検索することは保証しない。
- 単一検索式には**図鑑番号のみ**を列挙。ランキング同一番号の全フォームが抽出対象・検索可能で、GameMaster内のフォーム数より欠損がなく、CP例外も不要な場合だけ採用する。進化先が高評価・未評価で保護されたものは入れない。
- 「Show Evolutionary Line」ONで図鑑番号検索は自動展開されないとのコミュニティ報告があるが、Pokémon GO実機での保証はない。OFF推奨。ON使用時は**実際に進化先が混入しないか照合する**。検索に含める図鑑番号は名前による自動展開を避けるための安全寄りの設計であり、動作確認前の一括博士送りは非推奨。
- お気に入り除外ONの場合は1本に `&!favorite` を付け、OFFではこれを付けない。UIの切替で自動再生成し、ON/OFFと最終検索式を表示。Webアプリはお気に入りマークを操作しない。
- 数字による単一検索に含まれなかった対象は詳細検索に残す。画面に「対象にした数・対象外の数」を表示。1本だけで全種を網羅したと誤認させない。
- 入力CPや個体値を元に個別判定するものは別途読み取り履歴連携が必要。

## 出力の安全性

- 検索式の種名はGameMaster図鑑番号と照合した英語名だけを使う。英語名が取得できない／同番号で一致しない場合は日本語のまま出力せず「要確認」に送る。日本語名は確認一覧の表示専用。\n- 複合検索ではPokémon GOのOR演算子（カンマ）がAND（&）より優先されるため、検索式は**同じ共通条件の種名だけカンマでまとめてから**、`&shadow` / `&!shadow` と地域／CP／お気に入りを適用する。
- 通常とシャドウ、アローラ／ガラル／ヒスイ／パルデアを分離。地域種が存在する場合、基本種側はその地域を `!alola` などで除外。すべての自動検索式に `&cp-1500` を付与。既定で `&!favorite`。
- けしん／スピード／性差／通常とは違う姿など、検索文字列による厳密な識別が確認できないものは「要確認」として自動検索式に**含めない**。漏れの件数と名称を表示する。
- 同じ条件のポケモンを最大90種・1200文字まで1本の検索式にまとめる（Androidオーバーレイ取込上限2000文字未満）。条件の異なるシャドウ・地方の姿・進化後CPに基づく範囲は混ぜない。途中で除外した個体を黙って捨てない。
- **Pokémon GOの「Show Evolutionary Line」はOFFにすること。** ONにすると個別種名の検索が進化系統へ拡大し、弱い進化前から強い進化後が誤って選ばれ得る。検索式で `+Species` は使わない。
- GO側のニックネームが種名検索に一致する可能性など、検索エンジンの実機挙動は別途確認が必要。表示候補を削除・博士に送る処理は実行しない。
- 出力結果を本当に要らない個体と断定しない。育成予定・イベント限定技・レア個体・進化先の評価などを手動で保護する。

## 画面と連携

- Web: `https://pokemoniv-production.up.railway.app/app?tool=low-score`
- 正規のブラウザ接続（既存Cookie / アクセスキー）を使い、認証済み `POST /app-api/low-score` で計算。APIキーをURLに埋め込まない。
- Web上で「検索式を作成」→分割検索式ごとにコピー可能。「オーバーレイ用データをコピー」「Androidオーバーレイへ送る（対応版）」もある。
- Web→Androidの専用形式（従来の二行ペア、`pokemoniv-overlay-v2` とは別）:
  ```json
  {"format":"pokemoniv-search-queue-v1","source_date":"2026-10-15","items":[{"search":"アギルダー,マケンカニ&!shadow&cp-1500&!favorite"}]}
  ```
- 新形式は検索式だけを保存し、名前を**空欄**にする。SQLite既存schemaを維持しつつ、検索のみでチェック完了扱い。オーバーレイでは「名前」ボタンを非表示にする。旧形式とそのチェック・再コピー動作は維持する。
- 読み取りアプリ側の「厳選リスト取り込み」画面に保護色の丸い「低スコア個体を検索（Web）」ボタンを追加し、既定ブラウザで上記URLを開く。
