## 今回の実験

`tools/evaluate_rl_fixed_selection.py` は、既存のネイティブPvPoke 3対3環境・公開観測・v1/v2学習器を再利用する**診断専用の任意実験**。

- 学習時と評価時に、**自分の6-3選出を同一の合法アクション `0,1,4|4`** へ固定する。
- 相手の3体と先発は、事前に固定したseedから試合ごとに変える。相手の非公開選出・IV・技を方策に渡さない。
- 対戦中は通常の学習器が公開状態から戦術を決定する。
- 全滅まで正常に終わった試合だけが選出・戦術の価値を更新し、時間切れ・未対応などは学習しない。
- 評価は学習済み・未学習の両方に同じ自己選出と同じ対戦条件を与え、合法行動、公開状態、状態・行動ヒット率、正常終了率、完走同士の勝敗を検証する。
- 既存の固定CPUは元の独立した選出を使う。従って**固定CPUとの比較は「同一自己選出」の戦術比較にならない**。純粋な戦術比較は学習済み vs 未学習のみ対象とする。
- 評価開始時には両方の学習器を同じ方策乱数seedで初期化する。相手の秘匿情報や`private_replay()`は学習器へ送らない。
- 学習や評価の上限はそれぞれ32試合。大規模学習は行わない。

実行例:

```bash
PYTHONPATH=.:tests python -m unittest test_rl_fixed_selection
PYTHONPATH=.:tests python tools/evaluate_rl_fixed_selection.py --policy v2 --train 12 --evaluate 6 --seed 12
```

## 判断基準

- 自己選出固定で戦術状態・学習済み行動のヒットが出れば、**自己選出の変化**が以前のゼロヒットに寄与した可能性がある。ただし正常終了試合数、敵の選出、ランダム技の消費順にも影響されるため、原因の唯一性は証明しない。
- それでもヒットがゼロなら、同じ自己編成でも学習例の少なさ・相手の異なる選出・状態表現の細かさが残る可能性が高い。
- 固定CPUの全時間切れは、まだ対戦ルールの不具合を意味しない。結果を敗北として扱わない。
- 修正対象は診断実験、テスト、CIのみ。PvPokeエンジン、旧v1/v2モデル、チェックポイント、実サービス・本番DBは変更しない。
