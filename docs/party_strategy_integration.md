# パーティ構築への詳細戦略統合

調査基準: main `558726d2af1cb6fa02332c8eec5ba73f5ab5eb35`。
設計書と現行コードを照合した結果、個別詳細分析は利用可能だが、構築探索へ未接続、ペアのpressure/absorbは未計算だった。

## 実装した範囲

- 既存の2-2ビームサーチと反復交換を一次探索として維持。最大3案を共通の重要度上位・同重要度では対応が弱い最大3相手仮説で詳細比較する。
- 通常技限定2-2で相手最大HPの50%以上を削る役割、0-2で最初のゲージ技を生存してから通常技で15%以上削るかシールドを奪う役割を実イベントで判定する。
- 双方1枚温存の固定方針（技非公開）での対応を比較する。標準・温存・通常技限定のうち対面ごとの最大Ratingを合成する方式は採用しない。
- 初手と引き先を各案で固定し、既存のHP/energy/shields引継ぎモデルで標本内の後追いを評価。標準PvPokeを参照する限定分岐であり、残り2体の連携・再交代・交代タイマーは未評価。
- 静的な未対応重みと深刻度を優先し、同等案を役割指標で比較。通常技25、受け25、温存35、後追い15という説明可能な仮の配分。後追いの種族条件が不足する場合は残りを正規化する。
- 重要な条件がunknownの場合、全候補の一次順位を維持する。受ける前に対戦が終わる場合も受け役なしと断定しない。既知の担当が1体あれば、その役割の存在は確定できる。
- ペアごとに攻守の補完と別に、通常技・受けの担当と、その役割で相方の弱点を補う相手を表示する。標本外と未評価を明示する。
- UIで統合の有効/無効を選択・保存できる。旧保存データも読める。候補構築の別案を反映でき、固定枠は維持する。1体だけの交換候補の順位は従来の静的評価。
- 応答の新旧判定は実際の計算要求のスナップショットと照合する。パーティ名など計算に無関係な入力で結果を破棄せず、技や方針を変更した古い結果は破棄する。ブラウザーテストの待機引数も修正し、失敗時に画面状態を記録する。

## 計算量・保存

基準6体と最終3案の和集合は最大24体。詳細は24×3×4=288セル。交代prefix最大4件、chase最大8件で、要求数の上限は300（prefixの内部計算があるため最大対戦数は304）。500行のメタでもこの上限を超えないテストを追加。

詳細セルは既存の専用SQLiteテーブルと16 MiBの容量制限を再利用。同一ジョブ内のメモ化も追加し、キャッシュ退避後の同条件再計算を防ぐ。技・IV・CP・レベル・初期状態・方針・データ/エンジン版はキーへ含め、重要度と役割閾値は分析だけを再実行する。標準Ratingだけから詳細を推測しない。

既存の共有ワーカー予約、認証、Origin検証は変更なし。IV結果ZIP、保存済みパーティ、永続ボリュームの削除・初期化なし。追加データはJSONの任意フィールドだけで、DB移行は不要。ロールバックは以前のデプロイへ戻すか統合チェックを外す。新しい保存データは旧コードでも余剰フィールドとして扱える。

## 検証・引継ぎ

- 局所の新規統合テスト: 実エンジン、候補構築と自動補完、固定枠、順位逆転、unknown、重要な唯一回答の保護、300要求上限、再利用、キャンセル、旧データ保護。
- 既存Python/JavaScript回帰、324セルの標準計算一致、観測情報の不変性を維持する。
- モバイルブラウザーテストに統合結果、役割表示、候補反映、設定保存/復元、統合無効時の未評価表示を追加。ローカル環境ではChromium取得が失敗したため、Dockerビルドとブラウザー操作はGitHub CIで確認する。
- 大会での役割閾値と重みの妥当性、Android実機、本番の認証済み重計算は別途検証が必要。指標は勝率ではない。

優先度3以降は独立した追加作業とする。既存の合法なメタ技仮説は個別に扱うが、相手IV4条件の感度分析、頑健性専用評価、交代タイマー、大会ルール変更、手動役割タグ、完全3対3シミュレーションは追加していない。メテノも不正確な固定戦略へ置き換えず、既存の非対応を維持する。

計算条件と分析条件を分け、重い一次処理の後に予算付きの二次処理を置く構成は、検索推薦や価格比較にも再利用できる。unknownは0点と別の状態として持つことが、欠測データで誤推薦しないための要点。
