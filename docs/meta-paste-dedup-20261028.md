# メタ入力の重複統合と直接貼り付け

## 問題と根拠

アップロードのプレビューは `_validated_rows` から計算用 `load_meta` を呼び、重複も検証エラーとして全体を拒否していた。合成した90技構成に2つの重複を足した入力で「91行 重複; 92行 重複」を再現し、新しいプレビューで入力92行→保存90技構成になることを検証した。ユーザーのファイル自体は未受領のため、実ファイルの91/92行の内容を確認したわけではない。

## 変更

- ファイルと貼り付けの両方で、同じ種ID・技3列の重複を最初の1行へまとめる。空白・大小文字・シャドウの出力用末尾表記を考慮し、最初の行と順番は保持。
- 技違い、通常とシャドウ、ゲージ技の並び順違いは別の技構成として保持。
- 保存前に入力行数・保存する技構成数・統合した重複数と元の行番号を表示。自動保存しない。
- 「メタを貼り付け」→「貼り付けた内容を確認」→名前を付けて「別のプリセットとして保存」。ファイル作成もクリップボード読み取り権限も不要。通常の貼り付け操作を使う。
- ファイル読み込み後も同じ欄で編集可能。編集すると前のプレビューを無効化し、再確認が必要。
- 80KBと重複統合後500技構成の上限を維持。不正な種・技・列数は従来どおり拒否し、重複整理後も入力元の行番号を報告する。

## 実装・互換性

`pvpoke_meta_live.py` の共通の入力整理をプレビュー・従来の保存・名前付き保存から利用する。計算用の重複チェック自体は厳しいまま残し、重複した対戦相手を二重に数えない。

`pvpoke_meta_presets.py` では確認時と保存時に同じ整理とSHA256照合を実施。`pvpoke_app_ui.py` はファイルと貼り付けを同じ確認処理へ集約。古い内容の保存、遅い応答による誤保存、連打を防ぐ。

既存のメタ・履歴・デフォルト・お気に入りを自動移行・書き換えしない。追加API・追加ライブラリ・保存スキーマ変更はない。ChatGPT用PvPoke MCPへの接続は行わない。

## 検証

- ローカル回帰253件成功、UI JavaScript10ファイル成功。
- 元の91/92行の重複エラーと、新しいプレビュー・保存の回復を再現テスト。
- 行順・技違い・シャドウ・大小文字・空白・500件・80KBの境界、重複と不正行の混在、古いSHA256、データ保持を確認。
- 実HTTPで貼り付け相当のプレビューから名前付き保存まで検証。
- ブラウザQAには320/390pxで貼り付け→確認→明示保存、重複表示、保存後の入力クリア、デフォルト保持の確認を追加。本番アカウントを使わないテスト用応答で検証する。Dockerビルド・ブラウザQA・配備の最終状態は当該PRを参照。
- Android実機での長押し貼り付けと、ユーザーの実ファイルの再アップロードは未確認。

## 学習と復旧

入力の便利さと計算の厳密さを分ける。入り口では余分な重複を整理し、計算に渡す時点では重複のないデータを保証する。同じ整理をプレビューと保存で共有すると、「確認した内容と保存結果が違う」という事故を防げる。

重複判定は集合を使い入力行数に比例する処理。種名だけでまとめると技違いやシャドウが失われるので、計算エンジンと同じ4項目をキーにする。整理前の行番号も残すことで、エラーの場所が分かる。

コードをrevertして旧版を再配備すれば復旧できる。保存データの形式を変えていないため、復旧時のデータ移行は不要。
