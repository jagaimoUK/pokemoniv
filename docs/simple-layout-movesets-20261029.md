# Automatic reader import, compact layout and exhaustive moveset comparison

The reader's existing `#ivdata=` fragment is validated, removed from the address bar and imported after authentication/catalog/meta loading. Successful import focuses and scrolls to comparison settings. It preserves the normal import parser's CP, source records, status and evolution groups. An active calculation defers new handoff data; failed imports retain the text for correction. No handoff starts battles.

Move settings are the last, collapsed panel. Primary buttons have a minimum 48 px height. Nicknames refresh once after each result panel instead of after every row; deterministic move aliases are cached per move pool. Automatic comparison defaults ON; manual mode still calculates only the selected moves. Every legal fast move × unordered pair of distinct charged moves from the installed catalog is queued with all actual input IVs. The worker runs sequentially. No default-only prescreen or silent combination limit is used. This can take substantially longer on the first exhaustive run, especially species with large move pools. The progress notice shows the total configuration count. Completed full matrices can be reused with the existing exact-condition/version cache. The default entry bound increases from 20 to 128 to avoid evicting a normal 30-profile batch purely by entry count; the 200 MB and 7-day bounds remain. `PVP_RESULT_CACHE_MAX_ENTRIES` permits 1..512 entries.

Strength is measured against the selected meta, all input IVs, modes and six shield conditions. A profile is retained if its full-matrix mean Rating reaches the configurable threshold (default 450 as an explicit interpretation of “near 500”), offers a strictly >500 win condition unavailable from any other profile's input IVs, or ties for the highest mean as a fallback. A win union is a configuration-level available matchup, not a claim that every IV wins. All profiles and exact mean Ratings remain visible in a collapsed comparison. No ranking is inferred from the sparse recommendation examples.

Recommendations from retained configurations are combined by exact IV. When several retained configurations recommend the same IV, its highest per-IV mean recommendation supplies the adopted moves, evidence and nickname. Configuration-specific equivalent IVs are expanded before choosing, since equivalence may differ across moves. Independent source CP/occurrences are retained. Cross-configuration dominance/equivalence claims are cleared. The merged set can exceed four individuals; each underlying configuration still uses the established box-first selection policy. Nonselected IVs are listed as additional candidates, rather than given unsupported cross-profile dominance claims.

Move-mode nicknames use grade + species code + three 2-character move codes (at most 11 characters). Recognizable reserved codes include Scratch=Sc, Thunder Punch=TP, Ice Punch=IP, Swift=Sw, High Horsepower=HH. Collisions within a species' move pool receive deterministic alternatives and each nickname has a legend. Existing manual-mode names and two-line/v2 Android exports stay compatible. A physical IV shared across evolutions uses the first target's adopted move nickname for all stages; the legend states which evolution its move codes describe.

Game-data/calculation content identity is returned from the verified archive manifest. Automatic multi-profile batches reject unknown revisions and stop when that identity changes, including on resume. Profiles are also checked for identical meta, mode, species and matchup axes before aggregation. A server update therefore cannot silently combine old and new move damage calculations. This detects installed updates; downloading upstream updates is a separate existing process.

Tests cover full-matrix averages and strict 500 boundaries, axes, exhaustive combinations including Swift variants, weak defaults, exclusive wins, fallback, exact-IV adoption, equivalent expansion, sequential/resumed execution, forced recalculation flags, update rejection, authentication and same-tab handoff, CP preservation, failure recovery and existing export contracts. A Chromium smoke test exercises the real DOM at 390×844 and 1280×900 with fixture APIs; it does not claim physical Android/GO validation or real Ursaluna matchup ratings.
