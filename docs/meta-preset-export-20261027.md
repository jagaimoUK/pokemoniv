# メタプリセットのPvPoke向けコピー

## 使い方

1. 比較設定で対象のメタプリセットを選ぶ。
2. 「PvPoke用にコピー」を押す。
3. PvPokeのBattle画面でMultiまたはMatrixを選び、対戦相手一覧のImport/Exportに貼り付けてImportする。CP1500を選ぶ。
4. PvPokeで種・技を確認、編集する。戻す場合は4列のCSVをTXT/CSVに保存し、厳選アプリの「カスタムメタを追加」から別名で保存する。

100件超は最大100件ずつのコピーに分ける。例：250件なら「1〜100」「101〜200」「201〜250」の3組。PvPokeでは各組を別のグループとして確認する。500件を一度に貼ると公式の対戦用一覧では100件以降が取り込まれないため、全件を1回でコピーするボタンにはしていない。取り込み先がチーム6体の欄の場合は上限が異なるので、対戦相手のカスタムグループを使う。

クリップボードの利用がブラウザに拒否された場合は、同じ場所に手動コピー用の読み取り専用欄を表示する。コピー操作ではプリセット・デフォルト・お気に入り・履歴・計算条件を変更しない。

## 形式と根拠

PvPoke公式 `PokeMultiSelect.quickFillCSV` と `convertListToCSV` を確認。

取得元: https://github.com/pvpoke/pvpoke/blob/d98f52174e01f8f67414bc6973599788d098c10e/src/js/interface/PokeMultiSelect.js

- 種ID,通常技,ゲージ技1,ゲージ技2の4列。見出しや説明、個体値、レベルは付けない。
- シャドウ種IDの `_shadow` と、ダメージ補正を指定する `-shadow` は役割が異なる。`feraligatr_shadow` は `feraligatr_shadow-shadow` で出力。既存の補正指定には二重付与しない。
- 個体値・レベルは保存元のメタ定義にないため出力しない。PvPoke側の設定を使う。厳選アプリの「詳細」計算4モードをこのCSVに混在させない。
- 同種の技違いを順番どおり保持。シャドウ・通常も区別する。

## 実装

- `pvpoke_meta_presets.py`: 保存形式からPvPokeの形式への読み取り専用変換。100件区切り。元のIDとSHA256照合で古い画面の内容の取り違えを防ぐ。
- `pvpoke_web.py`: ローカルの読み取り専用エクスポートAPI。
- `pvpoke_bridge_core.py`, `pvpoke_mcp_remote.py`: 既存の認証済みWeb APIに追加。ChatGPT用PvPoke MCPの接続は使わない。既存サーバーのWeb経路のみ。
- `pvpoke_app_ui.py`: 選択欄横のコピーボタン、分割ボタン、手動コピー欄。通信中に選択が変わった場合は古い応答を捨てる。
- 追加ライブラリ、データ移行、スキーマ変更なし。公式データ取得は開発時だけ。コピー操作がPvPokeの外部サイトにデータ送信することはない。

## 検証

- 自動テストでカスタム・既存メタ・公式プリセットの出力、通常/シャドウ/補正指定済み、技違い保持を確認。
- 1/100/101/500件の境界値と、分割データを連結したときの全件一致を確認。
- 実HTTPでIDとSHA256の伝達、認証、古い画面・不正IDの拒否、保存と計算を変更しないことを確認。
- UIで自動コピー拒否時の代替欄、APIエラー、遅い応答と選択切替、古い分割ボタンの無効化を確認。
- ピン留めした公式取り込み関数のコピーを互換性テストで実行し、実際の出力が読み取られ、種・技・シャドウ補正・件数が保たれることを確認。ブラウザの手動実機確認と区別する。
- Android ChromeとPvPoke実画面の貼り付け操作は未確認。個体値やレベルをPvPokeで編集して列を追加したCSVは、従来どおり厳選アプリの4列アップロード対象外。

ローカル回帰246件中245件成功、1件はLinuxプロセスメモリ計測を環境上スキップ。UI JavaScriptテスト10ファイル、Python/JavaScript構文、git diff --check成功。Dockerビルドと本番配備の最終状態はPRのチェック・配備記録を参照。

## 学習と復旧

保存用の形式と外部サービス用の形式を分け、「変換する境界」を1か所に置く設計。内部データを直接書き換えるより既存の計算を守りやすい。外部の仕様が変わったらこの変換と契約テストを修正する。単にコピーできたかだけでなく、受け手がシャドウ補正まで正しく理解するかを確かめることが重要。

旧版へのコードrevert・再デプロイで復旧可能。保存データに変更を加えないのでデータ復元作業は不要。
