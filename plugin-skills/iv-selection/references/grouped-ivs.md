# 種名見出しの個体値割当と連続厳選

## 入力の意味
種名の見出しから次の種名見出しまでを一つの区間として読む。
`#カメール` はその区間をカメールだけに、`#カメール カメックス` は同じ区間を両種へ割り当てる。空行で区間を終了しない。行頭の `#` の後の空白は任意。
`# これ以降カメールとカメックス` のような明確な同義表現も同じ区間指定として扱う。

見出しに列挙された対象だけを使う。3段進化でも残りの進化形は自動追加しない。空区間を直前のIVの再指定と解釈しない。
見出しなしの通常入力は既存の単一種ルールを使う。対象のないIV、未知/曖昧な種名やフォルム、0～15以外のIVを勝手に割り当て・修正・除外しない。全入力を先に検証し、必要な不足情報だけ確認する。
種名中の空白を機械的に分割せず、確認済みの種名/IDとして解決する。通常/shadowを維持し、区分が曖昧なら確認する。

## 具体例
入力：

```text
個体値厳選
#カメール
0,11,12
3,13,8

#カメール カメックス
2,15,13

#カメックス
2,15,13
1,14,12
```

同じ技構成を使う場合の計算候補：

| 対象 | IV（入力順、同一対象の重複計算は一回） |
|---|---|
| カメール | 0/11/12、3/13/8、2/15/13 |
| カメックス | 2/15/13、1/14/12 |

2/15/13は両種に必要であり、進化形をまたいで一回に削減しない。
同じカメックスの2/15/13の二つの出現は一回の計算にまとめ、元の行との対応を保持する。

## 技とグループ
グループのキーは `species + 通常/shadow + fast + charged1 + charged2 + batch_mode + CP上限 + 最大Lv`。
種IDがshadowを含む場合も区分を維持する。種名の表記違いは確認済みの同一IDとして統合する。
明示された技を優先し、技省略時は確認済みの**同種**の設定/プリセットを使う。複数種の技が不明なら必要な種についてだけget_catalog等で確認する。読み込み済みの同じカタログを種ごとに再取得しない。
進化形ごとに技の有効性とCP1500以下・Lv50以下への調整を検証する。同じIVでも種族値・レベル・対戦結果は流用しない。
種類別/区間別の明示技が異なる場合は別グループにする。複数種への技指定の適用範囲が不明なら確認し、片方の技を無断で他種へ適用しない。
上限を超える入力を切り捨てない。分割が必要なら既存経路で全Ratingを保持し、同一グループの全候補を合わせて比較する。分割内のunique_gt500やdominatedをグループ全体の指標と誤認しない。

## 実行順
1. 全区間を読み、対象・IVの対応を保持して各グループを作る。候補の入力順とグループの初出順を維持する。
2. 全グループの種・技・IV・モードを確認する。省略/sはsimple、dはdetailed。各グループに全6/24条件を適用する。
3. Project原本を一回読み、実際の正規化SHA256を計算してサーバーメタを照合・必要時同期する。同じ依頼の間に原本/メタが変わったら再検証する。
4. グループ一つをrun_iv_selectionへ送る。candidateは**単一のオブジェクト**、ivsは数字3つの行だけ。見出し、種名配列、複数candidateを現在のMCPへ渡さない。実ハッシュをexpected_meta_sha256に渡す。
5. runningならそのrun_refで完了まで取得する。doneなら返却レポートを使い、重複してget_statusやget_selection_digestを呼ばない。
6. 全モード・条件・候補数・相手数・Rating件数・excluded・全候補差分・抜粋フラグを検証する。推薦に不足する根拠がある場合だけ、**このジョブが最新のうちに**補足照会する。根拠/取得済みRatingをグループにひも付けて保持する。
7. 完了後に次グループへ進む。run_refが更新されるので、前グループの取得を後回しにしない。ユーザーの「次」を待たない。失敗時は実行済み・取得済み・未実行を区別し、古いZIPで穴埋めしない。

## 評価・出力
全候補から既存の重要対面・不利シールド・代替性の基準で選ぶ。種類や技構成の異なるグループ間で完全支配判定をしない。
最終表示は `カメール` / `カメックス` など対象種ごとに分ける。同種の技構成が複数なら対象見出しに技も短く付記する。
推薦順位はグループごとに振り、各個体のIV・S/A候補・具体的役割・短い実測根拠・英語検索式を表示する。同じIVが両進化形で採用価値を持てば両方に載せる。
推薦数を制限せず、CSV・計算表・進捗表・所要時間は通常の回答に付けない。速度改善を実測なしで断定しない。
